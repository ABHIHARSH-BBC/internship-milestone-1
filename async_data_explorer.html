Asynchronous Architecture Patterns

1 Input Debouncing

As keystrokes happen, a timer is continuously reset. The API call fires only after a pause of 600ms. This prevents excessive network floods, saves rate limits, and stops spamming the backend API.

2 AbortController & Request Cancellation

When a user submits a new search while a previous request is still in-flight, abortController.abort() cancels the open network stream immediately. This guarantees that stale responses cannot overwrite newer results (race condition prevention).

3 Parallel Async Processing via Promise.all

Instead of sequentially fetching the user profile and then waiting to start fetching repositories, both are requested concurrently using Promise.all(). This reduces overall waiting latency by 40–50%.

4 Explicit State Machine Pattern

The UI deterministically switches between strict mutually exclusive states: Idle → Loading → Success | Empty | Error. No visual ghosting or orphaned spinners can occur.
